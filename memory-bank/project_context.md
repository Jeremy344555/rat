# Контекст проекта RAT (Remote API for Testing)

## Общая информация о проекте

### Название и назначение
**RAT (Remote API for Testing)** — это open-source расширение для платформы 1С:Предприятие, предназначенное для автоматизации интеграционного тестирования и удаленного управления данными информационных баз 1С.

### Правообладатель и лицензия
- **Разработчик**: BIA Technologies, LLC
- **Лицензия**: Apache License 2.0
- **Период разработки**: 2021-2025
- **Сайт компании**: [bia-tech.ru](http://www.bia-tech.ru)

## Бизнес-контекст и проблематика

### Решаемые проблемы
1. **Автоматизация тестирования 1С**: Необходимость проведения интеграционных тестов без ручного вмешательства
2. **Удаленный доступ к данным**: Потребность во взаимодействии с базами 1С из внешних систем
3. **Стандартизация API**: Отсутствие единого стандартизированного подхода к работе с данными 1С извне
4. **Интеграция с CI/CD**: Включение тестов 1С в процессы непрерывной интеграции

### Целевая аудитория
- **Разработчики 1С** - для автоматизации тестирования решений
- **QA-инженеры** - для создания автоматизированных тестов
- **DevOps-специалисты** - для настройки CI/CD процессов
- **Системные интеграторы** - для создания интеграционных решений

### Альтернативы и конкурентные решения
Проект создан как альтернатива существующим подходам:

| Подход | Ограничения | Преимущества RAT |
|--------|-------------|------------------|
| **OData** | Сложность сценариев, только GUID идентификаторы | Удобные форматы идентификаторов, простота сценариев |
| **Стандартный веб-сервис 1С** | Полная замена объектов, нет частичных обновлений | Поддержка PATCH операций |
| **Прямое подключение к БД** | Нарушение целостности, обход бизнес-логики | Соблюдение бизнес-правил 1С |

## Архитектурные принципы

### Основные принципы проектирования
1. **RESTful архитектура** - следование принципам REST API
2. **JSON сериализация** - использование примитивных типов (DTO)
3. **OpenAPI спецификация** - самодокументируемый API
4. **User-friendly подход** - максимальное удобство для тестировщиков
5. **Расширяемость** - простота добавления новой функциональности
6. **Кастомизация** - возможность адаптации под конкретные конфигурации

### Технологический стек
- **Платформа**: 1С:Предприятие 8.3.20+
- **Язык программирования**: 1С (BSL)
- **API стандарт**: OpenAPI v3.0
- **Формат данных**: JSON
- **Архитектурный стиль**: REST
- **Документация**: RapiDoc
- **Тестирование**: YAXUnit
- **Среда разработки**: EDT (Eclipse Development Tools)

## Функциональные возможности

### Основные функции
1. **CRUD операции** для объектов метаданных 1С
2. **Управление регламентными заданиями**
3. **Работа с движениями документов**
4. **Интеграция с Vanessa Automation**
5. **Автогенерация API документации**
6. **Поддержка серверных выражений**

### Поддерживаемые объекты метаданных
- **Полная поддержка**: Справочники, Документы, Планы видов характеристик, Планы счетов, Планы видов расчета, Планы обмена, Регистры сведений (независимые), Бизнес-процессы, Задачи
- **Только чтение**: Перечисления, Регистры сведений (подчиненные регистратору), Регистры накопления, Регистры бухгалтерии, Регистры расчета

### Интеграция с Vanessa Automation
- **200+ готовых шагов** для автоматизации тестирования
- **Поддержка Gherkin синтаксиса**
- **Библиотека известных шагов**
- **Генератор сценариев**

## Структура проекта

### Организация репозитория
```
rat_community/
├── exts/rat/                    # Основное расширение
├── tests/                       # Модульные тесты (YAXUnit)
├── fixtures/configuration/      # Тестовая конфигурация
├── features_scenario/           # Сценарии тестирования
├── doc/                        # Документация
├── documentation/              # Техническая документация
└── tools/                      # Инструменты разработки
```

### Ключевые компоненты
1. **HTTP-сервис RAT** - основной API endpoint (`/test-api`)
2. **47 общих модулей** - бизнес-логика расширения
3. **8 подсистем** - функциональное разделение
4. **Тестовая инфраструктура** - 50+ тестовых модулей
5. **Документация** - пользовательская и техническая

## Процесс разработки

### Методология разработки
- **Test-Driven Development** - любое изменение покрывается тестами
- **Continuous Integration** - автоматизированная проверка изменений
- **Code Review** - все изменения через merge request
- **Документирование** - обязательное описание новой функциональности

### Инструменты разработки
- **EDT** - основная среда разработки
- **Git** - система контроля версий
- **YAXUnit** - фреймворк для модульного тестирования
- **BSL Language Server** - статический анализ кода
- **Pre-commit hooks** - автоматическая проверка качества кода

### Стандарты качества
- **Покрытие тестами** - обязательное для всех изменений
- **Статический анализ** - соответствие стандартам BSL
- **Документирование API** - автогенерация OpenAPI спецификации
- **Код-ревью** - обязательная проверка всех изменений

## Развертывание и эксплуатация

### Требования к инфраструктуре
- **Веб-сервер**: IIS, Apache с поддержкой 1С
- **СУБД**: MS SQL Server, PostgreSQL, IBM DB2
- **ОС**: Windows, Linux
- **Сетевые требования**: HTTP/HTTPS доступ

### Процесс установки
1. **Получение релиза** - скачивание .cfe файла с GitHub
2. **Установка через конфигуратор** - стандартная процедура 1С
3. **Настройка безопасности** - отключение защитных режимов
4. **Публикация HTTP-сервиса** - настройка веб-сервера
5. **Тестирование доступности** - проверка endpoints
