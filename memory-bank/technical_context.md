# Технический контекст решения RAT (Remote API for Testing)

## Обзор решения

**RAT (Remote API for Testing)** — это расширение для платформы 1С:Предприятие, предоставляющее REST API для интеграционного тестирования и автоматизации работы с данными информационных баз 1С.

### Основное назначение
- Обеспечение удаленного доступа к данным 1С через стандартизированный REST API
- Интеграция с системами автоматизированного тестирования (Vanessa Automation)
- Автоматизация операций CRUD (Create, Read, Update, Delete) для объектов метаданных 1С
- Управление регламентными заданиями через внешние системы

## Архитектура решения

### Платформенные требования
- **Платформа**: 1С:Предприятие 8.3.20+
- **Режим совместимости**: 8.3.20+
- **Тип решения**: Расширение конфигурации (AddOn)
- **Язык разработки**: 1С (BSL - Built-in Scripting Language)
- **Префикс объектов**: "Рат"

### Структура расширения

#### Основные компоненты
1. **HTTP-сервис** (`HTTPService.RAT`)
   - Базовый URL: `/test-api`
   - Поддерживает все HTTP методы (GET, POST, PUT, DELETE)
   - Автоматическая маршрутизация запросов

2. **Подсистемы** (8 подсистем):
   - `РатПубличный` - публичный интерфейс
   - `РатОписаниеСервиса` - документация API
   - `РатАдаптацияФункциональности` - адаптация под конкретные конфигурации
   - `РатРасширениеФункциональности` - расширение возможностей

3. **Общие модули** (47 модулей):
   - **Сервисные модули**: `РатСервис`, `РатСпецификация`, `РатOpenAPI`
   - **Работа с данными**: `РатИнформационнаяБаза`, `РатМетаданные`, `РатТипыДанных`
   - **Сериализация**: `РатJSON`, `РатСериализация`, `РатПреобразования`
   - **Интеграция с VA**: `РатШагиВанессыСервер`, `РатШагиВанессыКлиент`
   - **Утилиты**: `РатОбщий`, `РатКоллекции`, `РатСтроковыеФункции`

#### Ключевые модули и их назначение

##### Модуль `РатСервис`
```bsl
// Основной обработчик HTTP-запросов
Функция ЗапросAPI(Запрос) Экспорт
// Генерация OpenAPI спецификации
Функция Спецификация(Запрос) Экспорт
// HTML-интерфейс для документации
Функция СпецификацияИнтерфейс(Запрос) Экспорт
```

##### Модуль `РатШаблоныАдресов`
- Система маршрутизации URL-шаблонов
- Поддержка динамических параметров в URL
- Приоритизация маршрутов

##### Модуль `РатМетаданные`
- Анализ структуры метаданных конфигурации
- Определение доступных операций для типов объектов
- Построение схемы данных для API

## API Архитектура

### REST API Спецификация
- **Стандарт**: OpenAPI v3.0
- **Формат данных**: JSON
- **Архитектурный стиль**: RESTful
- **Документация**: Автогенерируемая с использованием RapiDoc

### Поддерживаемые HTTP методы
- `GET` - получение данных
- `POST` - создание данных и расширенный поиск
- `PUT` - обновление данных
- `DELETE` - удаление данных

### Структура URL-адресов
```
/{ТипМетаданных}/{ВидМетаданных}[/{ИдентификаторОбъекта}][/Действие]
```

Примеры:
- `GET /Справочник/Пользователи` - список пользователей
- `POST /Справочник/Пользователи/Поиск` - расширенный поиск
- `GET /Справочник/Пользователи/root` - конкретный пользователь
- `PUT /Справочник/Пользователи/root` - обновление пользователя
- `DELETE /Справочник/Пользователи/root` - удаление пользователя

### Специальные endpoints
- `/spec.json` - OpenAPI спецификация
- `/spec-ui` - интерактивная документация
- `/РегламентныеЗадания` - управление регламентными заданиями
- `/{Объект}/{ID}/Движения` - работа с движениями документов

## Система идентификации объектов

### Поддерживаемые идентификаторы по типам объектов

| Тип объекта | Порядок поиска |
|-------------|----------------|
| Справочники | Ссылка → ИмяПредопределенного → Код → Наименование |
| Документы | Ссылка → Номер |
| Перечисления | ИмяПредопределенного |
| Планы характеристик | Ссылка → ИмяПредопределенного → Код → Наименование |

### Форматы идентификаторов
1. **GUID** - `416073e3-cbcd-11df-a704-e61f132874ef`
2. **Предопределенные элементы** - `root`, `Приход`
3. **Коды/Номера** - `0000001`, `ДОК-001`
4. **Наименования** - `Основной склад`
5. **Составные ключи** (для регистров) - `значение1;значение2;значение3`

## Форматы данных

### Примитивные типы
- **Число**: `123.45` (разделитель - точка)
- **Дата**: ISO 8601 (`2023-12-01T15:30:00`)
- **Булево**: `true`/`false`, `1`/`0`, `Да`/`Нет`
- **Строка**: `"текстовое значение"`

### Ссылочные типы
Поддерживается 3 формата указания ссылок:

1. **Объект с полями**:
```json
{
  "type": "CatalogRef.Пользователи",
  "id": "416073e3-cbcd-11df-a704-e61f132874ef"
}
```

2. **Строка с типом**:
```json
"CatalogRef.Пользователи.416073e3-cbcd-11df-a704-e61f132874ef"
```

3. **Только идентификатор**:
```json
"416073e3-cbcd-11df-a704-e61f132874ef"
```

### Серверные выражения
Возможность выполнения кода 1С на сервере:
```json
{
  "Дата": "Вычислить(ТекущаяДата())",
  "Сумма": "Вычислить(100 * 1.2)"
}
```

## Система тестирования

### Тестовая инфраструктура
- **Тестовый движок**: YAXUnit
- **Количество тестовых модулей**: 50+
- **Типы тестов**: модульные, интеграционные
- **Покрытие**: основные сценарии использования API

### Фикстуры для тестирования
Отдельная тестовая конфигурация (`fixtures/configuration`) содержит:
- Справочники для тестирования
- Документы и их движения
- Регистры различных типов
- Регламентные задания
- Планы обмена

### Тестовые модули (примеры)
- `ОМ_РатИнформационнаяБаза` - тесты работы с ИБ
- `ОМ_РатJSON` - тесты сериализации JSON
- `ОМ_РатВиртуальныеТаблицы` - тесты виртуальных таблиц
- `ОМ_РатМетаданные` - тесты работы с метаданными

## Безопасность и ограничения

### Механизмы безопасности
1. **Проверка прав доступа** - использование штатной системы RLS 1С
2. **Валидация входных данных** - проверка типов и форматов
3. **Контроль сессий** - автоматическое управление сессиями HTTP
4. **Логирование операций** - фиксация всех операций изменения данных

### Ограничения
- Работа только с объектами, доступными текущему пользователю
- Зависимость от настроек публикации HTTP-сервисов
